# Kambis Executive Report Dashboard

Dashboard สรุปรายงานผู้บริหารของ Kambis อ่านข้อมูลสดจาก Google Sheets **8 รายงาน (264 ชีตย่อย)**
พร้อมตรวจสอบความถูกต้องของข้อมูลอัตโนมัติทุกครั้งที่อัปเดต

สร้างด้วย HTML / CSS / Vanilla JavaScript / Three.js และ Node.js server — **ไม่มี dependency ใด ๆ**

## เริ่มใช้งาน

```bash
node scripts/sync-sources.js    # อ่านลิงก์จาก "แบบฟอร์มรายงาน Kambis.txt" (ครั้งแรก / เมื่อลิงก์เปลี่ยน)
node server/server.js           # เปิด http://localhost:5173
```

ตรวจ parser และ engine วิเคราะห์ข้อมูล (110 ข้อ):

```bash
node --test tests/*.js
```

| ไฟล์ | ตรวจอะไร |
|---|---|
| `tests/smoke.js` | parser ของรายงานดอก + กฎวิเคราะห์ข้อมูล |
| `tests/supply.js` | วัสดุสิ้นเปลือง + ใบขอซื้อ .xlsx |
| `tests/cost.js` | งบรายรับ-รายจ่าย (กับดักของชีตต้นทุน) |
| `tests/ui.js` | ตรรกะฝั่งเบราว์เซอร์ที่ไม่แตะ DOM |
| `tests/server.js` | คูลดาวน์รีเฟรช + การกันข้อมูลเสียทับข้อมูลดี |

> ใช้ `tests/*.js` ไม่ใช่ `tests/` — Node 24 จะมองว่า `tests` เป็นโมดูลแล้วรันไม่ผ่าน

## กฎสำคัญ 2 ข้อ

1. **ลิงก์รายงานทุกอันอ่านจาก `แบบฟอร์มรายงาน Kambis.txt` เท่านั้น**
   ห้ามเขียน URL ของ Google Sheets ลงในโค้ด — ทุกอย่างผ่าน `config/sources.json` ที่ generate จากไฟล์ .txt
2. **ทุกครั้งที่อัปเดตข้อมูล ต้องรัน Data Analysis**
   `server/lib/analysis.js` ทำงานอัตโนมัติทุกครั้งที่ดึงข้อมูล ผลลัพธ์แนบไปกับ API และแสดงบน UI เสมอ

รายละเอียดทั้งหมดอยู่ใน [CLAUDE.md](CLAUDE.md)

| รายงาน | หน้า |

- **จอ < 768px** ปุ่ม ☰ เปิดแผงเต็มจอ เห็นครบทั้ง 7 ปลายทางในหน้าจอเดียว
- สถานะตัวกรองอยู่ใน URL ส่งลิงก์ต่อได้ และ **เปิดมาที่ปีล่าสุดที่มีข้อมูลเสมอ**
  ไม่ใช่ยอดสะสมตั้งแต่เปิดฟาร์ม
- **การ์ด "คุณภาพข้อมูล" อยู่ท้ายหน้าของทั้งสองรายงาน** บอกทั้งข้อผิดพลาดที่เจอ
  และ **รายการที่ชีตยังไม่มีข้อมูลให้** พร้อมระบุว่าต้องเพิ่มคอลัมน์อะไรที่ชีตไหน

## แท็บใหม่ในชีตถูกดึงมาเอง

กด **รีเฟรชข้อมูล** แล้วระบบจะไปสำรวจรายชื่อแท็บของทุกชีตใหม่ทุกครั้ง
เพิ่มแท็บของเดือนใหม่หรือครอปใหม่ในชีตแล้วเห็นได้เลย ไม่ต้องรัน `sync-sources.js`
และจะมีแถบแจ้งบนหน้าเว็บว่าเจอแท็บอะไรเพิ่ม/หาย/เปลี่ยนชื่อ

ปุ่มรีเฟรชครอบคลุม **ทุกรายงานรวมถึงชีตวัสดุ** และมี **คูลดาวน์ 2 นาทีที่ใช้ร่วมกันทุกคน**
เพื่อไม่ให้ยิงคำขอไป Google ถี่เกินจนโดนจำกัด — กดก่อนครบเวลายังได้ข้อมูลชุดล่าสุดกลับไป
พร้อมข้อความบอกว่าเหลืออีกกี่นาที (ไม่ใช่ error)

จะต้องรัน `sync-sources.js` ก็ต่อเมื่อ **เพิ่มลิงก์ชีตใหม่** ลงในไฟล์ .txt เท่านั้น
แล้วต้องรีสตาร์ทเซิร์ฟเวอร์ด้วย เพราะโค้ดฝั่งเซิร์ฟเวอร์โหลดเข้าหน่วยความจำครั้งเดียวตอนสตาร์ท

## ข้อมูลเสียจะไม่ทับข้อมูลดี

ออกแบบมาเพื่อกรณีที่ผู้บริหารกดรีเฟรชตอน Google ล่มพอดี

- ระบบตัดสินจาก **จำนวนแถวที่อ่านได้จริง** ไม่ใช่แค่สถานะ HTTP
  (Google ตอบ 200 พร้อมหน้า login ได้ ซึ่งจะได้ "สำเร็จ" ที่ 0 แถว)
- ดึงสดไม่ได้ทั้งหมด → เสิร์ฟ **ชุดข้อมูลดีล่าสุด** พร้อมติดธงบอกผู้ใช้ว่ากำลังใช้ของเก่า
- ชุดสำรองบนดิสก์เขียนแบบ atomic และ **จะไม่ถูกเขียนทับด้วยข้อมูลที่อ่านไม่ได้**
  รีสตาร์ทเซิร์ฟเวอร์แล้วข้อมูลยังอยู่ครบ
- `GET /api/health` รายงาน `dataHealth` (`good` / `partial` / `bad`) ให้ตัวเฝ้าระวังภายนอกเรียกดูได้

## ระบบล็อกอิน (สำหรับเปิดให้ผู้บริหารเข้าผ่าน domain)

ระบบจะเปิดใช้ล็อกอินอัตโนมัติเมื่อมีผู้ใช้อย่างน้อยหนึ่งคน

```bash
node scripts/manage-users.js add somchai --name "คุณสมชาย" --role exec
node scripts/manage-users.js list
```

| role | ดูรายงาน | ใช้ผู้ช่วย AI |
|---|---|---|
| `exec` | ได้ | ได้ (จำกัดจำนวนคำถามต่อวัน) |
| `viewer` | ได้ | ไม่ได้ |

- รหัสผ่านเก็บเป็น scrypt hash ไม่เคยเก็บรหัสจริง
- session เป็นคุกกี้ `HttpOnly` ที่เซ็นด้วย HMAC — JavaScript บนหน้าเว็บอ่านไม่ได้
- ใส่รหัสผิด 5 ครั้งจะโดนหน่วง 15 นาที
- เพิ่มหรือลบผู้ใช้แล้วมีผลภายใน 5 วินาที ไม่ต้องรีสตาร์ทเซิร์ฟเวอร์
- ลบผู้ใช้แล้ว session ที่ค้างอยู่ของคนนั้นใช้ไม่ได้ทันที

**เซิร์ฟเวอร์จะไม่ยอมเปิดสู่เครือข่าย (`HOST` ไม่ใช่ localhost) ถ้ายังไม่มีผู้ใช้เลย**
เพราะข้อมูลชุดนี้มียอดขาย ต้นทุน และรายชื่อลูกค้าจริง

### โหมดทดสอบ (ตอนยังไม่ตั้งเซิร์ฟเวอร์จริง)

อยากเข้าไปดูระบบก่อนโดยไม่ต้องสร้างบัญชี ใส่บรรทัดนี้ใน `.env`:

```bash
DEV_LOGIN=1
```

แล้วพิมพ์ชื่อผู้ใช้กับรหัสอะไรก็เข้าได้ หน้า login จะขึ้นแถบเตือน
และชิปบนหัว Dashboard จะเป็นสีเหลืองเขียนว่า "(โหมดทดสอบ)"

> โหมดนี้เท่ากับไม่มีระบบล็อกอิน **เซิร์ฟเวอร์จะปฏิเสธที่จะสตาร์ท** ถ้าเปิดโหมดนี้
> ค้างไว้พร้อมกับตั้ง `HOST` เป็นอย่างอื่นที่ไม่ใช่ localhost — ลบบรรทัดนี้ก่อนขึ้นเซิร์ฟเวอร์จริง

### ยังต้องเสริมเองตอนขึ้นเซิร์ฟเวอร์จริง

- **HTTPS** ผ่าน reverse proxy (Caddy / nginx)
- **ตัวคุมให้รันต่อเนื่อง** (systemd / pm2)
- **สำรอง `config/users.json`**
- ค่าของ reverse proxy: `proxy_read_timeout` ต้องยาวกว่าเวลาโหลดเต็มรอบ
  (ตอน Google ช้าใช้เวลาได้ถึง ~3 นาที ซึ่งเกิน default 60 วินาทีของ nginx)
  และต้องตั้ง `proxy_buffering off` ให้ `/api/progress` ไม่งั้นหน้าจอโหลดจะค้างที่ 0%

## คุณสมบัติ

- การ์ดกระจก Glassmorphism กดดูรายละเอียดได้ทุกใบ พร้อม chip บอกคุณภาพข้อมูลของแหล่งนั้น
- **งบรายรับ-รายจ่ายรายเดือน** — รายได้ ต้นทุน กำไรขั้นต้น EBITDA ค่าเสื่อมราคา EBIT
- **ออกใบขอซื้อวัสดุเป็นไฟล์ `.xlsx`** ได้จากหน้าเว็บ (เขียน ZIP + XML เอง ไม่ใช้ library)
  ราคาเอาจากชีตเสมอ ไม่เชื่อค่าที่เบราว์เซอร์ส่งมา
- ฉากหลัง Three.js (ละอองลอย + ดวงแสง) พร้อม fallback เป็น gradient เมื่อ WebGL ใช้ไม่ได้
- Loading Screen เดินตามความคืบหน้าจริงผ่าน SSE ทีละแหล่งข้อมูล จบด้วยขั้นวิเคราะห์ข้อมูล
- Responsive 375px → 1920px, สลับภาษา ไทย/อังกฤษ, โหมดสว่าง/มืด
- กราฟ Canvas 2D เขียนเอง: โดนัท, เส้น, แท่งแนวนอน, แท่งซ้อน, แท่งจับคู่, ไทม์ไลน์รอบปลูก
- **ผู้ช่วย AI** ถามคำถามเกี่ยวกับตัวเลขใน Dashboard ได้ เลือกโมเดลเองได้ พร้อมแสดง token ทุกคำตอบ

## ผู้ช่วย AI (ไม่บังคับ)

ช่องแชทมุมขวาล่างเรียก **Gemini ผ่าน Google AI Studio** ต้องมี API key จาก
[aistudio.google.com/apikey](https://aistudio.google.com/apikey)

สร้างไฟล์ `.env` ที่โฟลเดอร์โปรเจกต์ (คัดลอกจาก `.env.example`):

```bash
GOOGLE_API_KEY=...
```

ไม่ตั้งค่าก็ใช้ Dashboard ได้ตามปกติ ช่องแชทจะแสดงวิธีตั้งค่าแทน
key อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ถูกส่งมาที่เบราว์เซอร์ และไฟล์ `.env` ถูก gitignore ไว้

เลือกโมเดลได้ 3 ตัว — `gemini-3.5-flash-lite` (เร็วสุด) / `gemini-3.5-flash` (ค่าเริ่มต้น) /
`gemini-3.6-flash` (ละเอียดสุด) ทุกคำตอบบอกจำนวน token ที่ใช้และโควตาที่เหลือของวันนั้น

ผู้ช่วยตอบจากตัวเลขที่โหลดมาจริงเท่านั้น และถูกสั่งห้ามเดาไว้หลายข้อ เช่น
ห้ามเอารายได้รวมไปหารกรัมที่ขายเพื่อเดาราคาขายเฉลี่ย และห้ามหารต้นทุนด้วยผลผลิต
เพื่อตอบต้นทุนต่อกรัม — เพราะต้นทุนของเดือนหนึ่งเป็นของครอปที่เก็บเกี่ยวอีกเดือนหนึ่ง

> **หมายเหตุ 2 ข้อ**
>
> 1. การกดรีเฟรช Dashboard **ไม่ใช้ AI เลย** — เป็นการอ่าน CSV แล้ว parse ด้วย
>    JavaScript ล้วน ตัวเลข token ที่แสดงเป็นของช่องแชทเท่านั้น
> 2. บัญชี Google AI Studio **ระดับฟรี** อาจนำข้อมูลที่ส่งเข้าไปใช้ปรับปรุงบริการของ Google
>    ถ้าไม่ต้องการให้ข้อมูลธุรกิจถูกใช้แบบนั้น ต้องใช้บัญชีแบบเสียเงิน
