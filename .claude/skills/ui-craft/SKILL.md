# UI Craft — สิ่งที่อ่านโค้ดแล้วไม่มีวันเห็น

`responsive-ui` ตอบว่า **โครงหน้าควรเป็นอย่างไร** (เมนู breakpoint touch target)
ไฟล์นี้ตอบว่า **ผิวของมันควรเป็นอย่างไร** และ **จะรู้ได้ยังไงว่าไม่ได้ทำพัง**

---

## 0. กฎเหล็ก: ห้ามบอกว่าเสร็จโดยไม่เคยเห็นของจริง

> CSS ไม่มี error ทุกกฎถูกทีละข้อได้พร้อมกับผลรวมที่น่าเกลียด

**เคสจริง ส.ค. 2569 — ช่อง "ดูสต๊อก ณ วันที่" กลายเป็นกรอบซ้อนกรอบ**

```css
.filter-year   { border: 1px solid …; border-radius: 999px; }  /* เม็ดยาที่ครอบป้าย+ช่อง */
.filter-date   { border: 1px solid …; border-radius: 6px;   }  /* ช่องวันที่เดี่ยว ๆ ใน popup */
.filter-asof .filter-date { border-radius: 999px; }            /* เอาสองอันมาชนกัน */
```

สามกฎนี้ **ถูกต้องทุกข้อเมื่ออ่านทีละข้อ** `.filter-date` ถูกออกแบบไว้ให้เป็นช่องเดี่ยว
ในกล่อง popup ของรายงาน Dryflower ซึ่งที่นั่นต้องมีกรอบจริง ๆ พอเอามาวางในเม็ดยา
มันจึงลากกรอบของตัวเองเข้าไปด้วย ผลคือเส้นสองเส้นวิ่งขนานห่างกัน 1px
ไม่มี test ไหนฟ้อง ไม่มี exception ไม่มีอะไรเลย — จนผู้ใช้ส่งภาพหน้าจอมาให้ดู

**ผู้ใช้ไม่ควรต้องเป็นตัวตรวจของเรา** ตั้งแต่นี้ไป งานที่แตะผิวหน้าเว็บทุกชิ้นต้องจบด้วย

```bash
node .claude/skills/ui-craft/scripts/ui-audit.mjs "<url>" --shot-of="<selector ที่เพิ่งแก้>" --out=C:\tmp\x.png
```

แล้ว **เปิดรูปนั้นดูด้วยตา** (Read tool อ่าน .png ได้) ผลตรวจอัตโนมัติเป็นตาข่ายชั้นสอง
ไม่ใช่ชั้นแรก — ของที่ "ไม่ผิดกฎแต่ดูไม่ดี" มีแต่ตาที่จับได้

## 1. บันไดการแบ่งพื้นที่ — ใช้ขั้นที่เบาที่สุดที่ทำงานได้

เวลาต้องบอกว่า "ของสองชิ้นนี้คนละกลุ่มกัน" มีเครื่องมือ 5 ขั้น เรียงจากเบาไปหนัก
**ไต่ขึ้นทีละขั้นเมื่อขั้นก่อนหน้าไม่พอเท่านั้น** ห้ามกระโดดไปหยิบกรอบเป็นอย่างแรก

| ขั้น | เครื่องมือ | ใช้เมื่อ | ในโปรเจกต์นี้ |
|---|---|---|---|
| 1 | **ระยะห่าง** | เกือบทุกกรณี | `--sp-6` ระหว่างแผง · `--sp-5` ระหว่างการ์ด · `--sp-4` ในกลุ่ม |
| 2 | **พื้นต่างเฉด** | กลุ่มที่ต้องเห็นขอบเขตชัด | `--bg-raise` · `--glass-fill` |
| 3 | **เส้นคั่นด้านเดียว** | รายการยาวที่ต้องแยกแถว | `border-bottom: 1px solid var(--glass-border-soft)` |
| 4 | **กรอบครบสี่ด้าน** | ชิ้นที่ "หยิบจับได้" — ปุ่ม เม็ดยา การ์ด | `.filter-year` · `.card` |
| 5 | **เงา** | ยกระดับความลึกเท่านั้น (3 ระดับ: พื้นหลัง → การ์ด → modal) | `--shadow-card` |

> ระยะห่างระหว่างกลุ่มต้องมากกว่าระยะในกลุ่มเสมอ ถ้าทำข้อนี้ถูก ขั้น 3–5 มักไม่จำเป็นเลย

## 2. กฎกรอบ — "หนึ่งกลุ่ม = หนึ่งกรอบ"

1. **กล่องที่มีกรอบครบสี่ด้าน ห้ามแนบอยู่ในกล่องที่มีกรอบครบสี่ด้าน**
   นิยาม "แนบ" = ช่องว่างระหว่างสองกรอบ ≤ 6px ตลอดแกนใดแกนหนึ่ง
   เส้นสองเส้นวิ่งขนานกันโดยไม่ได้แบ่งอะไร = สิ่งที่ผู้ใช้เรียกว่า "รก"
2. **ตัวควบคุมที่อยู่ในกลุ่มต้องโปร่ง** `border: 0` + `background: transparent`
   กรอบเป็นหน้าที่ของกลุ่ม ไม่ใช่ของชิ้นส่วนข้างใน
   (`.filter-year__select` และ `.filter-asof .filter-date` ทำแบบนี้)
3. **มุมมนกล่องใน = มุมมนกล่องนอก − ระยะห่าง** (`r_in = r_out − gap`)
   กล่องในมนกว้างกว่ากล่องนอกเมื่อไร มุมจะเบียดกันจนดูเหมือนวาดพลาด
   ระยะห่าง 0 = ต้องใช้มุมเท่ากันเป๊ะ
4. **วงแหวนโฟกัสล้อม "สิ่งที่ผู้ใช้เห็นว่าเป็นชิ้นเดียว"** ไม่ใช่ล้อมชิ้นส่วนข้างใน
   ซึ่งก็คือกรอบซ้อนกรอบอีกแบบหนึ่ง — ใช้ `:has()` ยกวงแหวนขึ้นไปที่กลุ่ม

   ```css
   @supports selector(:has(*)) {
     .filter-asof:has(.filter-date:focus-visible) { outline: 2px solid var(--accent); outline-offset: 2px; }
     .filter-asof:has(.filter-date:focus-visible) .filter-date:focus-visible { outline: none; }
   }
   ```

5. **คลาสที่ออกแบบไว้ให้เป็นชิ้นเดี่ยว ห้ามยัดเข้าไปในกลุ่มโดยไม่ถอดผิวออกก่อน**
   นี่คือรากของเคสข้างบน — ก่อนใช้คลาสเดิมซ้ำ ให้ถามว่า "คลาสนี้เกิดมาเพื่ออยู่ตรงไหน"
6. **มุมมนทั้งหน้าต้องมาจาก `--r-*` ชุดเดียว** ขอบมนไม่เท่ากันในหน้าเดียวคือสิ่งที่
   ทำให้ดูถูกทันที (กฎเดียวกับ `responsive-ui` ข้อ 5)

## 3. ตัวควบคุมพื้นเมือง (native control) — ของที่ CSS แตะไม่ถึง

`<input type="date">` `<select>` `<input type="search">` มีชิ้นส่วนที่เบราว์เซอร์วาดเอง

- **`color-scheme` คือสวิตช์เดียวที่พลิกสีของชิ้นส่วนพวกนั้น** (ไอคอนปฏิทิน, scrollbar,
  พื้นของ dropdown) — `tokens.css` ตั้งไว้ครบทั้งสามชั้นแล้ว **ห้ามลบ**
  ถ้าลืมตั้ง โหมดมืดจะได้ไอคอนดำบนพื้นเขียวเข้มที่มองไม่เห็นเลย
- **ไอคอนปฏิทินย้อมสีตรง ๆ ไม่ได้** ทำได้แค่ `::-webkit-calendar-picker-indicator { opacity }`
  หรือซ่อนแล้ววาดเอง — ที่นี่เลือกหรี่ลง `0.55` ให้มีน้ำหนักเท่าป้าย ไม่แย่งสายตาจากตัวเลข
- **ค่าว่างของ `type="date"` แสดงตามภาษาของ OS** (`mm/dd/yyyy` บนเครื่องที่ตั้งเป็น en-US)
  แก้ด้วย CSS ไม่ได้ — เคยประเมินว่า "ยังไม่คุ้มที่จะเขียนเอง" แล้ว **ประเมินผิด**
  พอรวมกับ "ปฏิทินไม่ตามธีม" กับ "ไม่มีที่ใส่ปุ่มลัด" มันคือสามปัญหาที่แก้ทีเดียวได้
  ตอนนี้มี `ui/datepicker.js` แล้ว (~380 บรรทัด) เพราะ **เปลือกกล่องลอยมีอยู่แล้ว**
  ที่เหลือคือตาราง 7×6 กับเลขคณิตวัน — บทเรียน: ประเมินราคาของงาน UI จาก
  **ส่วนที่ยังไม่มี** ไม่ใช่จากภาพรวมของสิ่งที่เห็นบนจอ
- **ชื่อเดือน/วันภาษาไทยได้ฟรีจาก `Intl` ห้ามฝังตารางคำแปล** — `weekday:'narrow'` ให้
  `อา จ อ พ พฤ ศ ส` แต่ฝั่งอังกฤษได้ `S M T W T F S` ที่ซ้ำกันสองคู่ ต้องใช้ `'short'` แทน
  และ `th-TH` เปล่า ๆ ให้ **พ.ศ.** (2569) — อยากได้ ค.ศ. ให้ขอ Intl แค่ชื่อเดือน
  แล้วต่อปีจากสตริงเอง (สำนวนเดียวกับ `monthYear()` ใน `format.js`)
- `accent-color` ย้อม checkbox/radio/range ได้ทั้งชุดด้วยบรรทัดเดียว (ใช้แล้วที่ `.fdrop`)
- ความสูงของช่องกรอกใช้ `min-height` เสมอ **ห้าม `height` ตายตัว** เพราะ `--fs-scale`
  ขยับได้ แล้วตัวอักษรจะล้นกรอบ

## 4. คลังเทคนิค CSS สมัยใหม่ — อะไรใช้ได้ที่นี่ อะไรยัง

โปรเจกต์นี้ zero dependency ไม่มี build step ไม่มี PostCSS — **CSS สมัยใหม่คือ
ทางเดียวที่จะลดโค้ด JS ลงได้** ตารางนี้เป็นสถานะ ณ ส.ค. 2569
**ก่อนใช้ตัวที่ยังไม่ "widely available" ให้เช็ค webstatus.dev ก่อนทุกครั้ง**

### ชั้น A — ใช้ได้เลย (Baseline widely available)

| ของ | ใช้ทำอะไรที่นี่ |
|---|---|
| `:has()` | ยกวงแหวนโฟกัสไปที่กลุ่ม · การ์ดที่รู้ว่าตัวเองมีกราฟ · แถวที่มี finding |
| Container queries + `cqi` | `.kpi__value` ย่อขยายตามความกว้างการ์ดจริง (ใช้แล้ว) |
| CSS nesting | ลดการเขียนชื่อคลาสซ้ำใน `pages.css` ที่ยาว 1,100 บรรทัด |
| `color-mix()` | ผสมโทนจาก 4 สีแบรนด์แทนการฮาร์ดโค้ด `rgba(...)` ใน `tokens.css` |
| `oklch()` + relative color | ไล่เฉดที่ความสว่างเท่ากันจริง (ตาคนมองว่าเท่ากัน ต่างจาก HSL) |
| `@scope` | จำกัดขอบเขตสไตล์ของหน้าใดหน้าหนึ่งโดยไม่ต้องตั้งชื่อคลาสยาว |
| `inert` | ปิดการโฟกัสของเนื้อหาหลังแผงเมนู/modal แทนการไล่ตั้ง `tabindex="-1"` |
| `dvh` / `svh` + `env(safe-area-inset-*)` | แผงเต็มจอบนมือถือที่มีแถบ URL ยืดหดได้ |
| `accent-color` · `color-scheme` | ตัวควบคุมพื้นเมือง (ดู §3) |
| `text-wrap: balance` | หัวข้อการ์ด/แผงที่ตัดบรรทัดแล้วเหลือคำเดียวห้อยท้าย |

### ชั้น B — ใช้ได้แต่ต้องมีทางถอย (newly available)

| ของ | ใช้ทำอะไร | ทางถอย |
|---|---|---|
| `light-dark()` | ยุบ token 3 ชุดใน `tokens.css` เหลือชุดเดียว | **ยังไม่ทำ** — เป็นการรื้อไฟล์สีทั้งไฟล์ ต้องรัน validator สีใหม่ทั้งสองโหมด |
| Popover API | `.fdrop` ที่ตอนนี้ต้องแขวนไว้ที่ `document.body` เอง | ต้องคง JS เดิมไว้เป็น fallback |
| `@starting-style` + `transition-behavior: allow-discrete` | animation ตอนเปิด modal/popup โดยไม่ต้องใช้ timer ใน JS | ไม่มี animation = ยังใช้งานได้ |
| `field-sizing: content` | `.qty-input` ในใบขอซื้อที่ยืดตามจำนวนหลัก | ความกว้างคงที่แบบเดิม |
| `content-visibility: auto` | ตาราง 138 แถวของหน้า Supply | เป็นแค่ hint ไม่พังถ้าไม่รองรับ |

### ชั้น C — ยังไม่ใช้ (Chromium-first / ยังไม่ครบทุกเบราว์เซอร์)

`anchor-positioning` · `interpolate-size` / `calc-size()` · scroll-driven animations ·
`if()` · `sibling-index()` · customizable `<select>` · `prefers-reduced-transparency`

ของกลุ่มนี้ใช้ได้เฉพาะเป็น **progressive enhancement ที่หายไปแล้วไม่มีใครรู้**
ห้ามให้ layout หรือความสามารถหลักขึ้นกับมัน

### กฎการรับของใหม่เข้าโปรเจกต์

1. ห้ามทำให้ต้องเพิ่ม dependency หรือ build step
2. ห้ามฮาร์ดโค้ดสีนอก `tokens.css` (กฎนี้ชนะทุกอย่าง)
3. ไม่ใช่ชั้น A → ต้องมี `@supports` หรือพังแล้วยังใช้งานได้
4. ต้องตรวจครบ 2 โหมด × 2 ภาษา × {375, 1280} ก่อนถือว่าเสร็จ

## 5. ui-audit.mjs — ตาข่ายชั้นสอง

```bash
node .claude/skills/ui-craft/scripts/ui-audit.mjs "http://127.0.0.1:5199/#/supply" \
  --login=dev:dev --wait=.filter-asof --width=375,1280 --theme=dark \
  --shot-of=.supply-filter-bar --out=C:\tmp\bar.png

# ของที่ต้องกดถึงจะเห็น (popup · แผ่นเลื่อน · เมนู) — ไม่มี --click ก็ไม่เคยถูกตรวจเลย
# ซึ่งเป็นที่ที่กรอบซ้อนกรอบเกิดง่ายที่สุด เพราะกล่องลอยมีกรอบของตัวเองอยู่แล้ว
node .claude/skills/ui-craft/scripts/ui-audit.mjs "http://127.0.0.1:5199/#/supply" \
  --login=dev:dev --wait=.filter-asof --click=.dp-trigger --after=.dp__grid \
  --width=1280 --theme=dark --shot-of=.filter-pop --out=C:\tmp\cal.png
```

เปิดเซิร์ฟเวอร์ด้วย `DEV_LOGIN=1 PORT=5199 node server/server.js` ก่อน (ต้องล็อกอิน
เพราะมี `config/users.json` อยู่) รอบแรกอาจใช้เวลาถึง ~40 วิเพราะต้องดึงชีตจริง

ตรวจให้ 6 อย่าง — ทั้งหมดเป็นอาการที่ **ไม่มี error ให้เห็น**:

| ตรวจ | จับอะไร |
|---|---|
| กรอบซ้อนกรอบ | §2 ข้อ 1 — บอกช่องว่างทั้งสี่ด้านและแกนที่แนบมาด้วย |
| มุมมนกล่องใน > กล่องนอก | §2 ข้อ 3 |
| horizontal scroll | พร้อมรายชื่อ element ที่ล้นออกไปจริง |
| เป้ากด < 44px | เฉพาะตอนสั่ง width < 768 (วัดที่ `<label>` ที่ครอบ ไม่ใช่ตัว control) |
| **ปุ่มถูกกล่องแม่ตัดหาย** | ปุ่มที่โผล่ไม่พ้นขอบของกล่องที่ `overflow: hidden` |
| canvas กว้าง/สูง 0 | กราฟไม่ถูกวาดเพราะกล่องยังไม่เข้า DOM |
| exception + console.error | ของที่หลุดตอน render |

**บทเรียนจากกฎ "ปุ่มถูกตัด": เขียนผิดรอบแรก** ตอนแรกฟ้องทุกปุ่มที่อยู่ใต้ขอบล่างของ
กล่องแม่ — ซึ่งรวม**กล่องที่เลื่อนได้**ด้วย นั่นคือพฤติกรรมปกติของทุกแผงที่ยาวกว่าจอ
จึงได้ false positive ทันทีที่เอาไปยิงหน้าอื่น แก้เป็น "หยุดไล่ขึ้นเมื่อเจอกล่องที่เลื่อนได้"
= ฟ้องเฉพาะของที่ **ไปถึงไม่ได้จริง ๆ**

> ตัวตรวจที่ฟ้องเรื่องปกติ อันตรายกว่าไม่มีตัวตรวจ เพราะรอบถัดไปจะไม่มีใครอ่านมันแล้ว
> ทุกกฎใหม่ต้องยิงใส่**หน้าอื่นที่ยังไม่ได้แก้**ด้วย ไม่ใช่แค่หน้าที่กำลังทำอยู่

**เกณฑ์เป้ากดเชื่อได้ต่อเมื่อปลอมอุปกรณ์สัมผัสสำเร็จ** `mobile: true` ของ CDP
**ไม่ได้เปิด `@media (hover: none)`** ต้องปลอมด้วย `Emulation.setEmulatedMedia`
(`hover: none` + `pointer: coarse`) สคริปต์รายงาน `touchEmulated` กลับมาด้วย
ถ้าเป็น `false` มันจะข้ามการตรวจข้อนี้แทนที่จะรายงานเลขที่ผิด — เพราะเลขที่ผิด
จะทำให้ไปแก้ CSS ที่ไม่ได้พัง

### กับดัก specificity: ตัวแปรของคอมโพเนนต์ชนะกฎ 44px เสมอ

`@media (hover: none) { .dp__day { min-height: 44px } }` = specificity **0,1,0**
ส่วน `.dp--inline .dp__day { min-height: 34px }` = **0,2,0** → **ตัวหลังชนะทุกกรณี**
media query ไม่ได้เพิ่ม specificity ให้เลย

เจอจริงตอนทำปฏิทิน: ตัวแปรที่ตั้งให้เตี้ยลงเพื่อประหยัดที่ในกล่องแคบ ทำให้เป้ากด
บนมือถือเหลือ 32–34px เงียบ ๆ **ทุกครั้งที่เขียนตัวแปรของคอมโพเนนต์ที่ลดขนาดลง
ต้องไปเติมตัวแปรนั้นในบล็อก `@media (hover: none)` ด้วย** (เป็นญาติกับกับดัก
`.x[hidden]{display:none}` ที่จดไว้ใน CLAUDE.md — ต้นเหตุเดียวกันคือ specificity)

exit 1 เมื่อเจอปัญหา — ใช้ต่อท้าย `node --test tests/*.js` ได้

**วินัยที่ห้ามข้าม: กฎตรวจใหม่ทุกข้อต้องพิสูจน์ว่าจับของเก่าได้**
ใส่บั๊กกลับเข้าไปชั่วคราว → รัน → ต้องฟ้อง → เอาบั๊กออก
(ทำแล้วกับกฎกรอบซ้อนกรอบ: ฟ้อง `แนบแนวตั้ง · ช่องว่าง top:1 bottom:1` ตรงจุด)
ไม่งั้นจะได้ ✔ ที่ไม่ได้แปลว่าอะไรเลย ซึ่งอันตรายกว่าไม่มีตัวตรวจ

**ข้อจำกัดที่ต้องรู้** ตัวตรวจไม่รู้เรื่อง: ความหมายของสี · ลำดับสายตา · ป้ายที่เขียนกำกวม ·
ระยะห่างที่ถูกต้องตามกฎแต่ดูแน่น · **การเรียงตัวที่เหลื่อมกันไม่กี่ px** — ต้องดูรูปหรือวัดเอง

**วัดดีกว่าเพ่ง** เรื่องการเรียงตัว (ขอบซ้ายตรงกันไหม · ความสูงเท่ากันไหม) ตาคนดูรูป
ความละเอียดต่ำแล้วบอกไม่ได้ว่า 5px หรือ 0px — เขียนสคริปต์ CDP สั้น ๆ อ่าน
`getBoundingClientRect()` ของแต่ละแถวมาเทียบกันตรง ๆ จะได้คำตอบที่เถียงไม่ได้
(เคสจริง: แท่งกราฟคุณภาพข้อมูลเหลื่อมกัน 5px — ในภาพหน้าจอดูเหมือนตรงกัน)

> **กับดักของการถ่ายรูป: ของที่อยู่ต่ำกว่าขอบจอจะได้รูปเปล่า** `clip` ของ CDP ใช้
> พิกัดของหน้า ไม่ใช่ของ viewport ต้องส่ง `captureBeyondViewport: true` ด้วย
> (สคริปต์ใส่ให้แล้ว) ถ้าไม่ใส่จะได้ภาพสีพื้นล้วนโดยไม่มี error — แล้วจะสรุปผิดว่า
> คอมโพเนนต์หายไป ทั้งที่มันอยู่ครบ
