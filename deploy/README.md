# เอา Kambis Dashboard ขึ้นเซิร์ฟเวอร์

เอกสารนี้สำหรับคนที่ดูแลเซิร์ฟเวอร์ ไม่ใช่ผู้ใช้ Dashboard
โครงสร้างและกฎการทำงานของตัวระบบอยู่ใน [`../CLAUDE.md`](../CLAUDE.md)

**สรุป:** Node.js ไม่มี dependency เลย · รันเป็น container ตัวเดียว ·
มี nginx คั่นหน้าเพื่อทำ HTTPS · ข้อมูลที่ต้องคงอยู่มีสองโฟลเดอร์คือ `config/` กับ `data/`

---

## 1. สิ่งที่ต้องเตรียม

| อย่าง | หมายเหตุ |
|---|---|
| เครื่อง Linux + Docker Engine + Docker Compose v2 | RAM 1 GB พอ · ไม่ต้องมี Node บนโฮสต์ |
| subdomain ที่ชี้ A record มาที่ IP ของเครื่องนี้แล้ว | เช่น `dashboard.example.com` |
| nginx + certbot บนโฮสต์ | ทำ HTTPS และเป็นด่านเดียวที่เปิดสู่อินเทอร์เน็ต |
| `GOOGLE_API_KEY` จาก Google AI Studio | ไม่มีก็รันได้ แค่ปิดผู้ช่วย AI |
| ชื่อผู้ใช้/รหัสผ่านของทุกคนที่ต้องเข้าใช้ | ดูข้อ 4 |

---

## 2. ติดตั้ง

```bash
git clone <repo> /opt/kambis
cd /opt/kambis
```

**ต้อง `git clone` บนเครื่องเซิร์ฟเวอร์ ไม่ใช่ก๊อปแค่ image**
เพราะ `docker-compose.yml` ผูก `./config` กับ `./data` เป็น bind mount
ซึ่งจะ **บังไฟล์ที่อยู่ใน image ไว้ทั้งโฟลเดอร์** โฮสต์จึงต้องมี `config/sources.json`
(ไฟล์ที่ track ไว้ใน git) อยู่ก่อน ไม่งั้นเซิร์ฟเวอร์จะหาไฟล์ตั้งค่าไม่เจอและไม่ยอมสตาร์ท

```bash
mkdir -p data
sudo chown -R 1000:1000 config data   # uid 1000 = ผู้ใช้ node ในคอนเทนเนอร์
```

## 3. เขียน `.env` — เขียนใหม่ ห้ามก๊อปจากเครื่องพัฒนา

```env
GOOGLE_API_KEY=<คีย์จริง>
SESSION_HOURS=12
CHAT_QUOTA_PER_DAY=50
REFRESH_COOLDOWN_SEC=120
```

**ต้องไม่มีสองบรรทัดนี้เด็ดขาด:**

| ตัวแปร | ถ้ามีจะเกิดอะไร |
|---|---|
| `ALLOW_NO_AUTH=1` | ปิดด่านที่กันไม่ให้เปิดสู่เครือข่ายทั้งที่ยังไม่มีบัญชีใครเลย — subdomain จะเปิดยอดขาย ต้นทุน และรายชื่อลูกค้าให้ทั้งอินเทอร์เน็ต |
| `DEV_LOGIN=1` | พิมพ์ชื่อผู้ใช้/รหัสอะไรก็เข้าได้ (เซิร์ฟเวอร์จะไม่ยอมสตาร์ทเลยถ้าเจอคู่กับ HOST ที่ไม่ใช่ localhost ซึ่งเป็นการกันไว้อีกชั้น) |

`.env` ของเครื่องพัฒนามี `ALLOW_NO_AUTH=1` และ `HOST=0.0.0.0` อยู่ **การ `scp` ไฟล์นั้นมาทั้งอัน
คือช่องทางเดียวที่ทำให้ระบบนี้หลุดสู่สาธารณะโดยไม่มีอะไรกั้น**

ส่วน `TZ` · `HOST` · `PORT` · `TRUST_PROXY` ถูกตรึงไว้ใน `docker-compose.yml` แล้ว
ค่าใน `environment:` ชนะค่าใน `env_file:` เสมอ จึงแก้จาก `.env` ไม่ได้โดยตั้งใจ

## 4. สร้างบัญชีผู้ใช้

**ระบบล็อกอินจะเปิดก็ต่อเมื่อมีผู้ใช้อย่างน้อย 1 คนใน `config/users.json`**
ถ้ายังไม่มีใครเลยและ `HOST` ไม่ใช่ localhost เซิร์ฟเวอร์จะ **ปฏิเสธที่จะสตาร์ท**

```bash
docker compose build
docker compose run --rm kambis node scripts/manage-users.js \
  add Supakorn --name "Supakorn Arunsirinaphalai" --role exec
# ทำซ้ำทีละคน แล้วตรวจด้วย
docker compose run --rm kambis node scripts/manage-users.js list
```

| ค่า | ความหมาย |
|---|---|
| ชื่อผู้ใช้ | ใช้ล็อกอิน — `a-z A-Z 0-9 . _ -` ยาว 3–32 ตัว · **พิมพ์ใหญ่/เล็กไม่มีผล** |
| `--name` | **ชื่อที่ขึ้นช่อง "ชื่อ" บนใบขอซื้อ** และบนหัว Dashboard · ไม่ใส่มาจะถูกถามตอนรัน |
| `--role exec` | ใช้ผู้ช่วย AI ได้ (มีค่าใช้จ่ายจริงต่อคำถาม) |
| `--role viewer` | ดูรายงานอย่างเดียว — **ยังออกใบขอซื้อได้ตามปกติ** |
| `--quota N` | จำนวนคำถาม AI ต่อวัน (ค่าเริ่มต้น 50) |

รหัสผ่านถามตอนรัน (ขึ้นเป็น `*` ไม่ตกใน shell history)
ตั้งแบบอัตโนมัติได้ด้วย `KAMBIS_PASSWORD=... docker compose run ...` แต่ค่านั้นจะตกใน history แทน

### ความยาวรหัสผ่านขั้นต่ำคือ 6 ตัว และเป็นตัวเลขล้วนได้

เป็นค่าที่เจ้าของระบบเลือกเอง (ส.ค. 69) — **ต้องรู้ว่าแลกอะไรไป**
รหัส 6 หลักตัวเลขล้วนมีความเป็นไปได้แค่ 1,000,000 แบบ ตัวกันที่เหลืออยู่จริง ๆ คือ
การล็อก 15 นาทีหลังใส่ผิด 5 ครั้ง ซึ่งนับแยกตาม **IP + ชื่อผู้ใช้**
คนที่หมุน IP ไปเรื่อย ๆ จึงยังไล่เดาได้ ควรตั้งรหัสที่ยาวและไม่ใช่รูปแบบเดาง่าย
ให้ทุกคนก่อนเปิดสู่สาธารณะ (แก้ทีหลังด้วย `manage-users.js passwd <ชื่อผู้ใช้>`)

### `username.txt` ใช้ครั้งเดียวแล้วลบ

ไฟล์นี้ (ถ้ามี) เก็บรหัสผ่านจริงเป็นข้อความธรรมดา ใช้ตอนตั้งระบบครั้งแรกเท่านั้น
**ระบบไม่ได้อ่านไฟล์นี้ตอนทำงาน** — ลบทิ้งจากเซิร์ฟเวอร์หลังสร้างบัญชีครบแล้ว
(ถูก `.gitignore` และ `.dockerignore` ไว้แล้ว จึงไม่หลุดเข้า git และไม่ติดไปกับ image)

`config/users.json` เก็บแต่ scrypt hash ย้อนกลับเป็นรหัสจริงไม่ได้ — ลืมรหัสต้องตั้งใหม่ ไม่ใช่ไปเปิดดู

## 5. เปิดใช้งาน

```bash
docker compose up -d
docker compose logs -f kambis        # ต้องเห็น "ล็อกอิน: เปิดใช้งาน — ผู้ใช้ N คน"

# /api/health อยู่หลังด่านล็อกอิน จึงตอบ 401 เมื่อยิงโดยไม่มี session
# — นั่นคือคำตอบที่ถูกต้อง ไม่ใช่อาการพัง (ดู CLAUDE.md §8)
curl -si localhost:5173/api/health | head -1     # ต้องได้ 401
docker inspect kambis --format '{{.State.Health.Status}}'   # ต้องเป็น healthy หลัง ~3 นาที
```

จากนั้นวาง nginx:

```bash
sudo cp deploy/nginx/kambis.conf /etc/nginx/sites-available/kambis.conf
sudo sed -i 's/dashboard.example.com/<subdomain จริง>/g' /etc/nginx/sites-available/kambis.conf
sudo ln -s /etc/nginx/sites-available/kambis.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d <subdomain จริง>
```

## 6. ตรวจหลัง deploy

| ตรวจ | ต้องได้ |
|---|---|
| `curl -sI https://<sub>/` | `302` ไป `/login.html` (ยังไม่ล็อกอิน) |
| `curl -sI https://<sub>/api/reports` | `401` `AUTH_REQUIRED` |
| เปิดเว็บแล้วล็อกอิน | หน้าจอโหลด **เดินเปอร์เซ็นต์** — ค้างที่ 0% แปลว่า `proxy_buffering off` ยังไม่มีผล |
| `docker compose exec kambis date` | ต้องลงท้าย `+0700` — ถ้าเป็น UTC เลขที่ใบขอซื้อกับยอดสต็อกจะเลื่อนไปหนึ่งวันช่วงเที่ยงคืนถึง 7 โมงเช้า |
| ออกใบขอซื้อหนึ่งใบ | ช่อง "ชื่อ" ต้องเป็นชื่อจริงของคนที่ล็อกอิน · เอกสารพอดี A4 แผ่นเดียว |
| `docker compose restart` แล้วเปิดเว็บ | ต้อง **ยังล็อกอินอยู่** และเลขที่ใบขอซื้อเดินต่อ ไม่ย้อนกลับไป 001 |

ข้อสุดท้ายคือการตรวจว่า volume ทำงานจริง — ถ้าหลุด จะรู้ตัวก็ต่อเมื่อออกใบซ้ำเลขไปแล้ว

## 7. งานที่ต้องทำเป็นระยะ

### สำรองข้อมูล

```bash
tar czf kambis-backup-$(date +%F).tgz config/users.json data/purchase-requests/
```

| ไฟล์ | หายแล้วเกิดอะไร |
|---|---|
| `config/users.json` | ทุกคนหลุดล็อกอิน (เก็บ secret ที่ใช้เซ็น session ไว้ด้วย) ต้องสร้างบัญชีใหม่หมด |
| `data/purchase-requests/` | เลขที่เอกสารเริ่มนับ 001 ใหม่ = ซ้ำกับใบที่ส่งไปให้เซ็นแล้ว · สถานะ "รอของ" หาย |

`data/cache/` ไม่ต้องสำรอง สร้างใหม่ได้จาก Google Sheets เสมอ

### เมื่อมีคนเพิ่ม **ลิงก์ชีตใหม่** ในไฟล์ `แบบฟอร์มรายงาน Kambis.txt`

แท็บใหม่ในชีตเดิมระบบรับเองทุกครั้งที่กดรีเฟรช แต่ **ลิงก์ชีตใหม่รับเองไม่ได้**

```bash
git pull                                              # เอาไฟล์ .txt เวอร์ชันใหม่มา
docker compose exec kambis node scripts/sync-sources.js
docker compose exec kambis node --test tests/smoke.js
docker compose restart kambis
```

แล้วตรวจ `config/sources.json` ว่า `key` ไม่ซ้ำกัน — `PROFILES` จับจากคำในชื่อรายงาน
และไม่ตรวจ key ซ้ำ ถ้าซ้ำรายงานตัวแรกจะถูกเขียนทับแล้วหายเงียบ

### อัปเดตโค้ด

```bash
git pull && docker compose build && docker compose up -d
```

`config/` กับ `data/` เป็น bind mount จึงไม่ถูกแตะ — บัญชีและใบขอซื้อยังอยู่ครบ

## 8. กับดักที่รู้แล้ว

- **`ports` ต้องเป็น `127.0.0.1:5173:5173`** เขียนเป็น `5173:5173` เฉย ๆ คือเปิดพอร์ตดิบ
  สู่อินเทอร์เน็ต ข้าม nginx ไปเลย — ไม่มี HTTPS และคุกกี้ session จะไม่ติดธง `Secure`
- **`TRUST_PROXY=1` ขาดไม่ได้เมื่อมี nginx** ไม่งั้นทุกคนถูกมองเป็น IP เดียวกัน
  คนเดียวพิมพ์รหัสผิด 5 ครั้งจะล็อกทุกคนออกจากระบบ 15 นาที
- **`proxy_read_timeout` ต้อง ≥ 300s** รอบโหลดเต็มตอน Google ช้าใช้ถึง ~3 นาที
  ค่าเริ่มต้น 60 วินาทีของ nginx จะตัดสายกลางคันแล้วผู้ใช้เห็น 504
- **ปุ่มรีเฟรชมีคูลดาวน์ 2 นาทีร่วมกันทุกคน** กดก่อนครบเวลาได้ชุดล่าสุดกลับไป (200 ไม่ใช่ 429)
  ไม่ใช่อาการค้าง — เป็นการกันไม่ให้ยิง Google ถี่จนโดนจำกัดโควตา
- **ยังไม่มีหน้าจัดการผู้ใช้บนเว็บ** และผู้ใช้เปลี่ยนรหัสตัวเองไม่ได้ ทุกอย่างผ่าน
  `manage-users.js` บนเซิร์ฟเวอร์เท่านั้น — ตั้งใจให้เป็นแบบนี้ จะได้ไม่มีช่องทาง
  สร้าง/แก้บัญชีเปิดออกสู่อินเทอร์เน็ต
